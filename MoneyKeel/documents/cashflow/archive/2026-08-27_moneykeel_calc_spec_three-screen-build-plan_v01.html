The five corrections, ranked by risk

Only these touch code that other screens already depend on. Ranked by how much moves.

  1. actualMonthFlow MK-CF-F-005 — nothing moves. Zero callers, zero reach; only screens call it. The safest change on the list.
  2. salaryGrossByMonth MK-CF-F-060 — reaches 38 functions, and still nothing moves. The branch being deleted only ever ran when someone entered take-home instead of gross, which the new screen never does. Dead code.
  3. employerMatchMonthly MK-CF-F-078 — reaches 7. Collapsing three identical copies into one changes no number today. It stops them drifting tomorrow.
  4. requiredPayment MK-CF-F-023 — reaches 10, and this one does move numbers. Adding a fallback for a debt with no stated minimum raises the monthly debt figure for those people — today they see $0. Needs your ruling on the rule before it is written.
  5. incomeMonthlyGrid MK-CF-F-092 — reaches 22, and it should move them. Using the take-home a person typed instead of one derived by taxing gross changes take-home, surplus, essentials, the emergency test and the snapshot — toward the figure they entered.

What this means for the order

Twelve of the eighteen buildable items either use an unchanged function or add a new one that nothing else calls. Only two corrections move a number anyone sees, and one of those is the point of the exercise.

  1. The income screen first. Three new functions, one dead-code deletion, one de-duplication. Nothing else moves, and it is what makes take-home right everywhere downstream.
  2. Then This month. Two new functions and the safest correction on the list. The only open question is the debt-minimum fallback.
  3. Then Spending, except its Actual section. Three new functions, no corrections at all.
  4. Then the parked four, when the card provider is in place.
