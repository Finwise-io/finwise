#Change from v14Why, and what I measured
16Where the window Return refuses, it shows the exact rate per year instead of an em-dash. Screens 1 and 2. The summary trio, the window selector and each account walk read a rate; the refusal paragraph it replaces is gone, and the note beneath the trio says which kind of rate it is. Every other state of every screen is v14 exactly. Today that person sees an em-dash and a paragraph saying why there is no percentage — and they are exactly the person who most needs a rate, because they are actively adding money. The two methods are not rivals: measured, they agree to 0.018 of a percentage point wherever the Return answers (7.6161% against 7.6341% on a year with $10,000 added mid-way), because the Return refuses the moment its straight-line shortcut could be off by more than a point. So this fills the gap the refusal leaves and never contradicts it. One return is visible at a time.
16aThe alternative, if you prefer it. Every Return cell stays an em-dash and the rate sits in the note alone. Not drawn — say the word and it becomes v17. 16 keeps each trio complete, so a person always reads three figures. I recommend 16.
17Every colour is the app’s own token. Twelve rules: a gain #006300 (was #178F6B), a fall #A32D2D (was #C2483A), an amber caution #854F0B on #FAEEDA (was #B97F10 on #FDF1DC), quiet grey #76766F (was #9A9891 and #8A8A84), secondary text #6B6B66 (was #66655F), the screen behind the cards #F6F7F5 (was #F4F3EC), and the graph’s axis labels 11 points as the code draws them (were 8.5). Read from src/utils/theme.ts rule by rule. The app’s greys are darker on purpose — the file says textTertiary was darkened to meet WCAG AA because the old value was about 2.6:1 on white. #178F6B STAYS where the app really uses it: the wordmark, a link, and the value line, which ValueGraph strokes with Colors.primary.
